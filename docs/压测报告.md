# 压测报告

记录 2026-10-04（Asia/Shanghai）对本地 OpenAI 兼容代理的限额与压力测试。数字来自当次实跑，完整日志为 `youdao-luna-proxy-limit-test-2026-10-04.txt`（留在测试机，未纳入本仓库）。

被测服务以 `npm start` 启动。测试期间没有执行 git push。套件中的用例全部通过。

## 被测对象

这是本地的 OpenAI 兼容聊天代理，对外模型标签为 DeepSeek-V3。测试时 `/v1/models` 的列表仍可能显示 DeepSeek-V4。上游函数名固定为 `deepseek_r1`。本仓库当前的模型列表为 DeepSeek-V3，上游函数名仍是 `deepseek_r1`。

## 硬限制

代理只使用输入的最后 12000 个字符。约 16k 与约 32k 的输入都返回 HTTP 200，但开头标记已经丢失。16k 耗时约 23 秒，32k 耗时约 42 秒。

请求体大于 1MB 时返回 400。

`max_tokens` 不会转发到上游。响应里没有 `usage`。`finish_reason` 始终是 `stop`。

省略 `stream` 时默认走 SSE。需要一次性 JSON 的客户端必须显式传入 `stream: false`。

## 软限制与负载

本轮没有出现 429、502 或封禁。偶发 HTTP 200 且响应体为空。

短请求基线：平均 3.10 秒，p50 2.99 秒，p95 3.60 秒。

并发 1 到 50 全部成功。50 路并发的 p50 为 3.60 秒，p95 为 4.85 秒。混合多任务加到 50 时，结果为 49/50。

顺序请求 20 次全部成功。约 10 分钟轻负载为 24/24。

突发大约 2 请求/秒、持续 3 分钟，结果为 367/370。冷却 90 秒后，再以同样速率跑 2 分钟，结果为 229/231。

## 能力抽查

长文生成约 1322 个字符，耗时 20.7 秒。数学、代码、翻译三项冒烟检查为 3/3。

## 结论

作为日常 LLM 代理，在中等并发下可以使用。不要信任大约 8k 以上的上下文。这不是官方 API。
