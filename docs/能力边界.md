# 能力边界

这是本地 OpenAI 兼容的聊天补全代理，对接有道网页端 LLM（`https://luna-ai.youdao.com`）。它不是有道官方 API，也不是翻译服务。不需要 API Key 或 Cookie；每次请求单独取临时凭据，凭据不落盘、不回给客户端。

数字来自 2026-10-04 的实跑，详见 [压测报告](压测报告.md)。那次被测提交是 `b4a4bcf`。模型列表和未知 model id 的处理，以当前代码为准，和当时的列表不一致。

## 现在能做的

对外只有三个接口：`GET /health`、`GET /v1/models`、`POST /v1/chat/completions`。

`/v1/models` 只列出 `DeepSeek-V3`。请求里使用 `DeepSeek-V3`，或省略 model，都会按 `DeepSeek-V3` 返回。旧 id `DeepSeek-V4` 仍会被接受，响应里的 model 也写成 `DeepSeek-V3`。上游函数名固定是 `deepseek_r1`，换客户端 model id 不会换成另一个模型。其他 model id 返回 400。

省略 `stream` 或传入 `true` 时返回 SSE。要一次性 JSON，必须传 `stream: false`。

2026-10-04 的短请求基线是 5/5 成功，mean=3.10s，p50=2.99s，p95=3.60s。同质短请求齐射在 1、3、5、10、20、30、50 都判为 PASS；50 路是 50/50 HTTP 200，p50=3.60s，p95=4.85s。8 路混合突发约 2 请求/秒：180 秒 367/370（99.2%），冷却 90 秒后 120 秒 229/231（99.1%）。约 10 分钟、每 25 秒一次的轻载是 24/24。数学、代码、翻译冒烟是 3/3。长文那次是 chars=1517、cjk=1322、20.73s，完成标记还在。全套没有 429、502、连接重置或封禁。

按那次人工修正后的结论，它可以当单人日常代理，那次测到的中等并发也能用。并发上限没有被打到。

## 不要依赖的

拼好的对话只保留最后 12000 个字符（`slice(-12000)`）。1k、4k、8k 能同时回显开头和结尾标记。16000 字符耗时 23.30s、32000 字符耗时 42.48s，两次都是 HTTP 200，但开头标记已经丢了。不要信任大约 8k 字符以上的上下文。截断时 `finish_reason` 仍是 `stop`。

请求体大于 1MB 时本地返回 400 `Request body exceeds 1 MB`，不会打上游。

代码不读取、也不转发 `max_tokens` 和 `temperature`。实测 `max_tokens=8` 仍输出 82 字符。响应里没有 `usage`。`finish_reason` 恒为 `stop`。

空字符串 content 不会被拒，会打到上游。空 body、坏 JSON、没有文本消息，返回 400。

偶发 HTTP 200 且正文为空或近乎为空。那次大约是短齐射 2/30、混合 1/50、突发 3/370 和 2/231。

每次完成固定再请求上游三次：`/translate_llm/secret`、`/translate_llm/v3/uuid/generate`、`/translate_llm/v3/chat`。上游地址和协议可能在本地代码不变时改变。

默认监听 `127.0.0.1`，没有鉴权。不要把它暴露到公网，除非自己加上认证、限流和访问控制。
